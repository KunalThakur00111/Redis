# Redis project collaboration preferences

- Explain proposed code changes before editing, and wait for Kunal's go-ahead unless he has already authorized the change.
- When teaching C++ or Linux networking code, explain each function and system call in depth: its purpose, arguments, constants, return values, error cases, and a concrete example where useful.
- Change only what the requested task requires. Preserve unrelated variable names, formatting, behavior, and code structure. Never edit, reword, move, or delete existing comments unless the requested change strictly requires it. Do not add opportunistic refactors or cleanup.
- After editing, identify exactly what changed, why it changed, and how it was verified.
